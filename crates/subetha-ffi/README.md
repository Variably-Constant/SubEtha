# subetha-ffi

The C ABI for SubEtha. One header, `include/subetha.h`, and a library that
builds as a shared library, a static library and a Rust crate, for C, C++,
Go, Node and every other language that binds through C.

The ABI is unstable until its major version reaches 1; `subetha_abi_version()`
reports what a build carries. The surface arrives in tiers, in the order
published in `C_ABI_TIERS.md` at the repository root. This crate holds every
tier that document lists: the runtime, handle table, error model and adaptive
ring of tier 0; the rings, channels, stack and deque of tier 1; the shared
state of tier 2; the coordination families of tier 3; the transports of tier
4; and the probabilistic and specialist structures of tier 5. Which tiers
have passed the three-host acceptance gate is recorded in that document's
table, and the gate itself is described in the repository README.

## Building

```sh
cargo build -p subetha-ffi --release
```

produces, under `target/release`, the shared library (`subetha_ffi.dll` with
its import library on Windows, `libsubetha_ffi.so` with soname
`libsubetha_ffi.so.0` on Linux and FreeBSD, `libsubetha_ffi.dylib` on macOS)
and the static library (`subetha_ffi.lib` or `libsubetha_ffi.a`). The header
is committed at `include/subetha.h`; it is generated by cbindgen from this
crate, and `cargo test -p subetha-ffi` fails when the committed copy has
drifted from the Rust.

## The contract, in five sentences

`subetha_init(default_mode)` comes before every other call and
`subetha_shutdown()` before the library is unloaded; shutdown reports, on
stderr and in its return code, any handle the caller left open. Every
function returns `int32_t`: `SUBETHA_OK`, or a code `subetha_strerror()`
names, with the specifics of that failure in a thread-local buffer
`subetha_last_error_detail()` copies out. A handle is a 64-bit index and
generation, so a destroyed or forged handle is refused rather than
dereferenced. A panic inside any call is caught at the boundary: the call
returns `SUBETHA_E_PANIC`, the handle it ran on is poisoned until destroyed,
and `subetha_last_panic_message()` has the text. Each object is created in
strict mode, which starts no thread and writes into caller buffers, or
managed mode, which runs the background work the Rust API runs; the process
default is the one chosen at init.

## A ring in C

```c
#include "subetha.h"
#include <stdio.h>
#include <string.h>

int main(void) {
    if (subetha_init(SUBETHA_MODE_STRICT) != SUBETHA_OK) return 1;

    subetha_ring_options opt = {SUBETHA_MODE_DEFAULT, 0, 0};
    subetha_handle ring;
    int32_t rc = subetha_ring_create("/tmp/demo-ring", 1, 1, 1024, &opt, &ring);
    if (rc != SUBETHA_OK) {
        char why[256];
        subetha_last_error_detail(why, sizeof why);
        fprintf(stderr, "create: %s (%s)\n", subetha_strerror(rc), why);
        return 1;
    }

    uint32_t producer, consumer;
    subetha_ring_register_producer(ring, &producer);
    subetha_ring_register_consumer(ring, &consumer);

    subetha_ring_try_push(ring, producer, (const uint8_t *)"hello", 5);

    uint8_t slot[SUBETHA_RING_SLOT_BYTES];
    size_t len;
    rc = subetha_ring_pop_wait(ring, consumer, slot, sizeof slot, &len, 1000);
    /* A pop yields the whole slot, zero past the payload: len is 64 and
       slot holds "hello" followed by zeros. */
    printf("%d: %s\n", (int)rc, (const char *)slot);

    subetha_handle_destroy(ring);
    subetha_ring_unlink("/tmp/demo-ring", 1, NULL);
    return subetha_shutdown();
}
```

Another process attaches to the same prefix with `subetha_ring_open`, and
`subetha_ring_pop_wait` there parks on a waker in the mapping that this
process's push wakes. `subetha_ring_create_shm` and `subetha_ring_open_shm`
do the same in named shared memory.

## What a ring carries

The ring moves fixed slots of `SUBETHA_RING_SLOT_BYTES` bytes. A push
zero-fills the slot past its payload, and a pop yields the whole slot, so
the payload's own length does not survive; a caller that needs it carries it
inside the payload. `SUBETHA_RING_PAYLOAD_MAX` is the largest payload every
shape accepts; a push above it succeeds only in the single-producer
single-consumer shape.

## The families

Every family has a try form and a waiting form of its operations. The
waiting forms park on a consumer waker and a producer waker the ABI keeps
beside the backing, at `<prefix>.cwaker.bin` and `<prefix>.pwaker.bin` for
a file and `{name}_cwaker` and `{name}_pwaker` in shared memory, so a wait
in one process is ended by a push or pop in another. A wait ends with
`SUBETHA_OK`, `SUBETHA_E_TIMEOUT` when `timeout_ms` elapses,
`SUBETHA_E_RING_WAKER_FULL` when every waiter slot of the waker is taken
(`max_waiters` in the options sizes it), or `SUBETHA_E_DESTROYED` when the
handle is destroyed under the wait. Each family has `read_stats` into its
own `_stats` struct, `wake_all`, and an `unlink` that removes the backing
and its wakers by name and reports what it removed, what was missing and
what the OS refused.

| exact-order receiver | `subetha_ring_ordered_receiver`, `subetha_ordered_` | one consumer id of a stamped ring delivered in exact stamp order; the strategy follows the ring's stamp source and `flush` drains the window at the end of a stream |

| MPMC grid | `subetha_mpmc_` | one ring per producer-consumer pair |
| Vyukov ring | `subetha_vyukov_` | one bounded queue any number of producers and consumers share; the stuck-slot scan and heal a watchdog runs after a producer died |
| Lamport pair | `subetha_lamport_` | a producer handle and a consumer handle on one ring |
| broadcast ring | `subetha_broadcast_` | every registered consumer sees every item; the slowest gates the producer |
| pub/sub | `subetha_pubsub_`, `subetha_subscriber_` | a subscriber's position kept in memory or in a file it names; a lost position is reported and moved to the head |
| capacity ring | `subetha_capacity_` | morph to another capacity with the items in flight, compound morph, prewarm, and a second process attaching with `open` |
| locale ring | `subetha_locale_ring_` | anonymous, file and shared-memory backings with `migrate` between them, the managed request, and a second process attaching with `open` |

| shared stack | `subetha_stack_` | a bounded lock-free LIFO in a file, at an element size the caller declares |
| work-stealing deque | `subetha_deque_` | one owner pushing and popping the bottom, thieves in any process stealing the top; a thief handle's push and pop return `SUBETHA_E_DEQUE_NOT_OWNER` |
| pollable notifier | `subetha_ring_notifier`, `subetha_spsc_notifier`, `subetha_notifier_` | a consumer's own object an event loop watches, signaled by every push on the ring from any process; `native` hands out the file descriptor or event `HANDLE`, `drain` clears it, `wait` and `is_signaled` serve a caller without a loop |
| shared hash map | `subetha_hashmap_` | an open-addressed table in a file at key and value sizes the caller declares, keys hashed and compared as bytes; insert, insert-if-absent, get, contains, remove, compare-exchange under the entry's lock, a cursor walk, compact, clear |
| shared string arena | `subetha_arena_` | an append-only byte pool in a file; an intern returns a 64-bit reference packing offset and length that resolves to the same bytes from every process, by copy with `get` or in place with `view`; a read-only open for a process that may not write the file; clear. An intern appends and does not deduplicate, so the same bytes twice take the room twice and answer with two references; a caller wanting one copy per value keeps its own map, which is what makes an intern a bump of the cursor rather than a lookup |
| shared vec | `subetha_vec_` | a bounded, indexable, append-only sequence in a file at an element layout the caller declares; a push lands at the next index and publishes it once every earlier push has, get and set by index under the slot's SeqLock, pop, clear, a read-only open |
| shared slab | `subetha_slab_` | a fixed array of records in a file at a record layout the caller declares, addressed by the caller's own index with no length, allocator or free list; get and set under the slot's SeqLock, the slot's version, a read-only open |
| shared region | `subetha_region_` | a slot arena in a file at an element layout the caller declares, allocated from a free list in front of a bump cursor; a slot is named by a 32-bit index every process resolves the same way, so a pointer-bearing structure travels between them; allocate, free, get, set, clear |
| shared atomics | `subetha_atomic_` | a 32-bit, 64-bit or boolean counter or flag in a file every process operates on atomically; load, store, swap, add, subtract, and, or, exclusive-or and compare-exchange, each in a sequentially-consistent form and an `_explicit` form taking a `SUBETHA_ORDER_` value, as `<stdatomic.h>` shapes them |
| shared linked list | `subetha_list_` | a doubly-linked list in a file at an element layout the caller declares; a push returns the node's index, which names that node in every process, so a removal from the middle costs a splice rather than a walk; push and pop at both ends, get, set, and a walk from either end |
| shared B-tree map | `subetha_btree_` | an ordered map in a file at key and value sizes the caller declares, keys compared as unsigned bytes; insert, get, contains, remove, the smallest and largest entries, clear. One writer changes the shape while any number of readers retry through a version rather than lock |
| shared cell | `subetha_cell_` | one value in a file at a size the caller declares, written under a version a reader retries on, so it never sees half of one value and half of another; a reader that only wants to know whether it changed watches the version instead of the bytes |
| frame region | `subetha_frame_region_` | fixed-size blocks in a file for payloads too large to travel inside a ring slot: a producer takes a block, writes it and sends the index, a consumer reads it and frees it, and any consumer may free any block. This is the region an adaptive ring builds for itself when a frame outgrows a slot, reached directly. The free list runs through the blocks, so a free overwrites the first four bytes of the one it takes |
| epoch table | `subetha_epochs_`, `subetha_pin_`, `subetha_ticket_` | a counter in a file and the pins held against it, so a scan reads one fixed view while writers keep running. A pin and a ticket are `uint64_t` tokens: `subetha_pin_release(table, token)` lets a pin go and `subetha_ticket_publish(table, token)` makes a compound write visible. Both are visible to every attached process, which is what lets one process reclaim safely while another is mid-scan, and `subetha_epochs_held` reports how many of each are out |
| reader-writer lock | `subetha_rwlock_` | many readers or one writer across processes, with writer priority. A hold is a `uint64_t` token, not a handle: `subetha_rwlock_unlock(lock, token)` gives it back. The waiting acquires take a timeout and poll, since a release here signals nobody, and a destroy of the lock's handle releases every caller waiting on it and gives back every hold it issued |
| counting semaphore | `subetha_semaphore_` | a bounded number of permits any number of processes take and give back, for limiting how many of them work on something at once. A permit is a `uint64_t` token: `subetha_semaphore_release(sem, token)` returns it, and `subetha_semaphore_held` reports how many are out, which is where a leak shows. Three files carry the state: the count, the wakeup generation a release advances, and the waiter count |
| condition variable | `subetha_condvar_` | park until another process says something changed. The predicate stays with the caller, as it does in C: read `subetha_condvar_generation` first, check your own predicate, and hand that generation to `subetha_condvar_wait`, which returns at once if a notify has already moved past it. That is what stops a notify landing between the check and the wait from being lost |
| owner lease | `subetha_owner_lease_` | one process at a time holds a resource, and a holder that dies loses it. A lower process id preempts outright; a heartbeat that has fallen past the grace window marks a holder gone. The window is counted in epochs and nothing ticks them on its own, so whatever calls `subetha_owner_lease_tick_epoch` sets how quickly that happens. A payload of up to 48 bytes travels with the lease, readable and writable only by the holder |
| leader election | `subetha_leader_` | among the processes attached to one file, exactly one leads, and which one converges without a vote: the lowest live process id wins. Process ids are unique on a host, so a set of live processes always agrees, and it takes one compare-exchange rather than a quorum. The election term goes up on every handover, so a follower watching for a change polls the term rather than the process id |
| heartbeat table | `subetha_heartbeat_` | the lease and the election each track one holder; this tracks a whole fleet. Each process registers a slot and beats into it, and the slot carries the process id, the epoch it last beat at, a bitmap of the work units it has taken, and a role. A supervisor walks the slots to find who has gone quiet and what work they were holding when they went |
| holder table | `subetha_holders_` | the substrate under the epoch table's pins and tickets, reached directly: a fixed array of claimable slots, each carrying one `uint64_t` of the caller's own meaning and the process that claimed it. `subetha_holders_reap_dead` frees every slot whose process is gone, which is the question a bare count cannot answer. Claim in one step, or reserve and publish when the payload depends on state read after the slot is visible |
| shared fence clock | `subetha_fence_clock_` | a hybrid logical clock per participant and the global fence beneath which every one of them has been heard from. A participant ticks as it works and merges the clock that traveled beside a message, which is what makes the order total across processes: a merge takes the later of the two and steps it, so an event that caused another compares below it. The fence is the latest clock across live slots: every event any participant has recorded stands at or below it, so it is the point by which all of their work is accounted for. One participant publishes it on a schedule and the rest read it without walking the slots. A slot is a plain index, so a participant costs nothing to register and nothing to close |
| lazy value | `subetha_lazy_` | a value produced once across every process that asks for it, so a fleet starting together makes one request against whatever serves the value rather than one each. `claim` hands the right to produce it to a single caller and refuses the rest; the winner produces it however it likes and calls `publish`; the others `wait`, which returns as soon as the value is there. A claim stands across the caller's own code, so a claimant can die holding one: the claim carries the process that took it, `wait` answers `SUBETHA_E_LAZY_CLAIMANT_GONE` once that process is gone rather than waiting out a deadline for a publish that will never come, and `reclaim` frees it for the next caller. `publish` takes the claiming process id, so a caller that lost the claim cannot overwrite the winner's value |
| cross-process waker | `subetha_waker_` | parking and waking between processes, down on the platform's own futex - `WaitOnAddress` and the hardware monitor on Windows, `futex` on Linux, `_umtx_op` on FreeBSD - so a parked thread costs nothing until it is woken. A consumer parks at the sequence number it is waiting for and a producer that reaches that number wakes it; the sequence is the caller's own, a ring's write position or a job counter or anything a producer can compare against. `park` reserves a slot and returns a token, `wait` blocks on it and gives the slot back before returning, and `release` is for a parker that decides not to wait. A full table answers `SUBETHA_E_RING_WAKER_FULL`, which the caller handles by spinning on whatever it wanted - what it would do with no waker at all |
| shared value | `subetha_shared_arc_` | a region of shared memory kept alive by the processes holding it, and released when the last one lets go. Ownership is a holder table, one slot per holder stamped with the process that took it, so a holder whose process dies never releases and its slot is reclaimed by probing whether that process is still there - `reap_dead_holders` on demand, and an open that would otherwise report the table full does it first. `SUBETHA_ARC_UNLINK` removes the backing when the last holder releases, the `Arc` shape; `SUBETHA_ARC_KEEP` leaves it for a process attaching later. The region's length is fixed at create and the bytes mean whatever the caller decides: nothing here orders one holder's write against another's read, so a caller that mutates puts an atomic in the region or shares it under a lock. It is the same backing layout the Rust `SharedArc<T>` uses and records the region's length, so a Rust holder of a `T` and a C holder of `sizeof(T)` bytes share one value and a length that disagrees is refused |
| epoch barrier | `subetha_epoch_barrier_` | a rendezvous: each process waits at an epoch until the others reach it, so a round of work cannot begin anywhere before it has ended everywhere. What it promises is order, not duration - the early arriver does not pass until the late one is there, and nothing is said about how long either waits. It counts arrivals in one shared word and takes its notion of how many peers exist from a heartbeat table, so a process that dies between rounds stops being waited for once its slot goes stale rather than stalling the round forever. `_wait_quorum` releases on enough arrivals instead of all of them, for when a straggler must not hold the others, and every wait has a form that takes a deadline. It is built from a heartbeat handle rather than a path, so it counts peers in the same table its caller beats into |
| Sens-O-Matic | `subetha_sens_` | the reliable forward-correcting UDP endpoint. The unified sender and receiver switch erasure code on measured loss; the `_rlc_` and `_rs_` halves pin one code and report zero switches because they cannot switch. All six halves share one handle kind and one set of `send`, `poll`, `flush`, `finish`, `local_port` and `read_stats`; `finish` waits for the far end's acknowledgment of everything a sending half sent, retransmitting the rest, and is what ends a stream. With the `tls` feature `_sender_tls` and `_receiver_tls` seal every item and take DER bytes, since the TLS configuration types cannot cross the boundary; without it every entry point exists and answers `SUBETHA_E_NOT_SUPPORTED` naming the feature. Strict blocks on the calling thread; managed owns a runtime thread. The stats carry `missed` and `kernel_dropped`, each with a three-state report, because the three hosts differ in what their kernels will say and a zero paired with anything but `SUBETHA_DROPS_EXACT` is not a claim that none were lost. A unified receiver also counts what reached the process and was not delivered: `unroutable`, and on the sealed path `preauth_dropped`, `unopened` and `handshake_failures`, so a stream that never opens shows where it stopped |
| TCP and QUIC bridges | `subetha_tcp_bridge_`, `subetha_quic_bridge_` | a client or server half carrying items between a ring here and a peer there; `run` with a timeout and `read_stats`; the QUIC bridge takes its certificate as DER bytes |
| blocking bridge | `subetha_blocking_tcp_bridge_` | the same client and server halves over a blocking SPSC ring at each end: the client parks on the ring until an item arrives and ships what it drains, the server parks when its ring is full rather than dropping, so a consumer that stops draining ends the run with an error. Behind the `tcp-bridge` feature with the TCP bridge; `run` with a timeout and `read_stats` |
| virtual endpoints | `subetha_endpoint_` | a registry of named targets, each a local locale-ring handle or a remote address. A target is read together with the generation it was read at, and `_still_valid` asks whether that generation still stands: the Rust pinned endpoint borrows the registry for its lifetime, which C cannot honor, so the pair replaces the borrow. An unbound id reads as `SUBETHA_ENDPOINT_NONE` |
| quality-of-service policy | `subetha_qos_` | what a workload needs, held where a sidecar reads it on every scan and a caller changes it while traffic runs. Each field is its own atomic, so there is no call that writes the whole policy at once - it would look atomic and would not be - and `read` can return a mixture of two policies if a writer runs during it; every field it returns was real |
| Bloom, blocked Bloom, count-min, HyperLogLog | `subetha_bloom_`, `subetha_blocked_bloom_`, `subetha_cms_`, `subetha_hll_` | set-membership filters, a frequency sketch and a cardinality estimator, each with a `_suggest` that sizes it from a target; the sketch and the HLL answer estimates |
| histogram, reservoir, rate limiter, topology | `subetha_histogram_`, `subetha_reservoir_`, `subetha_rate_limiter_`, `subetha_topology_` | a histogram with `_percentile` and `_bucket_for`, a reservoir sampler with `_snapshot`, a rate limiter with `_try_acquire` and `_acquire_wait`, and a topology map recording fan-out and fan-in |
| versioned structures | `subetha_versioned_chain_`, `subetha_versioned_map_`, `subetha_versioned_slab_`, `subetha_laned_map_` | epoch-versioned structures where a reader pins an epoch and a writer sweeps or voids one once every reader has left it |
| bit vector | `subetha_bit_vec_` | a shared bit vector; `set`, `clear` and `toggle` each write what the bit was before into `was`, which is what makes `set` usable as a claim between processes |
| NaN-boxed values | `subetha_nan_` | one 64-bit word holding a double, a 32-bit integer, a boolean, nil or a tagged offset pointer. The only family with no handle and nothing shared: a value is a `uint64_t` the caller holds, none of these can fail on a handle, none takes a mode, and `subetha_init` is not required. Reading a value as the wrong type answers false and leaves the output untouched |
| LRU cache | `subetha_lru_` | a cache at key and value sizes the caller declares. `get` leaves recency alone and `get_and_touch` promotes; a miss leaves the value buffer exactly as it was; `evict_oldest` hands back both halves of what it dropped |
| directed graph | `subetha_graph_` | nodes and edges at value sizes the caller declares. Out-edges are walked with `first_edge` and `next_edge` to `SUBETHA_GRAPH_NIL` rather than returned as a list. An edge to an unallocated node is refused, removing an edge from a node that does not own it is refused, and node removal is not offered because every edge pointing at a node lives in another node's chain |
| time-point tile | `subetha_tile_` | sixteen lanes, each a version and a payload of up to `SUBETHA_TILE_MAX_PAYLOAD` bytes; a snapshot sees the lanes at or below its version, inclusive, and `visible_mask` answers all sixteen in one call. Version 0 is refused on insert, and a removed lane clears its version before its occupancy so a reused lane cannot be seen through its predecessor |
| content-prefix pointer | `subetha_umbra_` | sixteen bytes the caller holds, resolved against a `subetha_region_` handle, so each call borrows one handle. Four bytes of the value travel with it: a prefix mismatch rules equality out with no dereference, a match means resolve and compare, which is why the comparison is `_prefix_eq` rather than anything suggesting equality. Seven bytes of caller extension ride beside a tag |
| strategy-switching set | `subetha_universal_` | a set that moves between a vector and a hash map while it holds data, only when `_migrate` is called. The stats carry a `stamp` a reader compares across an operation, equal before and after meaning no migration interleaved, and the insert and contains counts a policy above the ABI decides on |
| cascade tower | `subetha_tower_` | levels of index slots over a leaf of values, at a depth set by how many intermediate levels the caller supplies; no maximum is imposed. Paths cross as caller-provided `uint32_t` arrays of exactly `depth` entries, and `get` checks every level of a path against the tower, refusing at the first level that no longer agrees rather than resolving whatever value now sits at its end |

A notifier is what a program with an event loop watches instead of parking
in a waiting form. `subetha_ring_notifier` or `subetha_spsc_notifier`
attaches one to a ring for the calling process; on Unix it is a named FIFO
held open for reading without blocking, which `poll`, `epoll` and `kqueue`
report readable while a signal is pending, and on Windows a named
manual-reset event a wait function returns from. Every push through the
ABI on that ring, from any process, signals every attached notifier: one
atomic load per push while nothing is attached, one write or event set per
notifier while something is. A signal stays until `subetha_notifier_drain`
clears it and means "something was pushed since the last drain": the
consumer drains, then pops until the ring is empty, and a push that lands
in between signals again. Beside a file-backed ring the record every
process reads is `<prefix>.notify.bin`, created with the ring, and the
Unix FIFOs are `<prefix>.notify.<index>`, all removed by the ring's
unlink and counted in its report; beside a
shared-memory ring the record is the region `{name}_notify` and the
notifiers are named from `{name}` in the same namespace, with the same
descriptor. Destroying the notifier's handle detaches it.

`subetha_ring_options` carries, beyond the mode, the waker size and the
managed scan interval: the stamps and contract of the adaptive ring; the
frame region geometry, `frame_block` bytes per block and `frame_blocks`
blocks, which creates the region at construction so a frame up to a block
travels past the slot (both zero leaves the region to be created at
`SUBETHA_RING_FRAME_DEFAULT_BLOCK` bytes on the first spilled frame); and
`shm_sddl`, a security descriptor for the shared-memory regions the object
creates, which a region mapped from another Windows session needs and
other platforms ignore. A C initializer that names the first three fields
and leaves the rest zero asks for none of these.

The stack and the deque take a `subetha_element_layout`: the element size,
its alignment, and a tag the caller chooses to name the element's type. The
region stores all three, and an attach that states another layout is
refused with `SUBETHA_E_RING_LAYOUT_MISMATCH`, so two programs that
disagree about what the bytes mean are never paired. A push copies at most
`element_size` bytes and zeroes the rest of the element; a pop yields the
whole element.

## Threads and the two modes

Every function is safe to call from any thread with respect to the handle
table. Whether two threads may drive one ring concurrently is the ring's own
contract: one registered producer id or consumer id belongs to one thread
at a time, and the ring's shape follows the live registrations. Strict mode
attaches nothing and starts no thread; the ring still morphs on
registration and on the pop path, which needs no pumping. Managed mode
attaches a shape sidecar that scans at `scan_interval_us`, which the caller
sets, and `subetha_handle_destroy` joins it.

## Installing for C consumers

```sh
cargo run -p xtask -- ffi-install --prefix /opt/subetha
```

builds the release library and lays out:

| Path | Contents |
|---|---|
| `include/subetha.h` | the header |
| `lib/libsubetha_ffi.so.0` and `lib/libsubetha_ffi.so` | the shared library under its versioned name and its unversioned link; `lib/libsubetha_ffi.0.dylib` on macOS; `bin/subetha_ffi.dll` with `lib/subetha_ffi.lib` as its import library on Windows |
| `lib/libsubetha_ffi.a` | the static library; `lib/subetha_ffi_static.lib` on Windows |
| `lib/subetha.def` | the export definition, Windows only |
| `lib/pkgconfig/subetha.pc` | `pkg-config --cflags --libs subetha` |
| `lib/cmake/subetha/` | `find_package(subetha)` with the targets `subetha::subetha` (shared) and `subetha::static` |

The static target carries the system libraries a static link needs, as
rustc reports them, and any library a dependency's build script ships from
inside the cargo registry is copied into `lib/` beside the static library
and referenced from there. `cmake-consumer/` is a CMake project with one
executable on each target; `cargo run -p xtask -- ffi-package-gate` installs
into `target/ffi-prefix`, builds and runs both, reports a missing `cmake` or
`pkg-config` as SKIPPED, and then compiles the same consumer directly with
the host's C compiler, shared and static, so the artifacts are proven on a
host without cmake.

## Tests

`crates/subetha-ffi-tests` compiles a C suite with the host's own compiler,
with every warning an error, and runs it from `cargo test`. The suite
exercises every family in one process; then, for each family, a C peer in
a second process attaches to a backing this process created and drains
what it produces through the file-backed wakers, eleven peers in one run.
The committed header and export definition are regenerated by this crate's
tests, and drift in either fails them.

The boundary itself, the handle lookup, the panic guard and the argument
checks, is 7.1 ns a call on this host. The atomic row is the clearest
view of it, since the work either side of the boundary is two
instructions: 15.4 ns through the ABI against 1.6 ns direct is 13.8 ns
for the pair's two calls. The other rows differ by 9 to 22 ns a pair,
and the frame row by 53, because a ring or channel call carries more
than the boundary: two handles, the ring and its producer or consumer;
the payload copied as bytes into and out of a slot; on every push a
check of the parked consumers and of the pollable notifiers, and on
every pop a check of the parked producers, none of which the direct
rows do; and the frame forms copy the frame both ways. The rows whose
direct work is itself tens of nanoseconds, the exact-order receiver and
the hash map, differ least because the boundary is the smallest part of
them.

A caller that moves items in bursts pays that once for the whole burst
through the `_many` forms, which take one handle lookup and one panic
guard for a run of operations. The items stay in the caller's own array:
`items` addresses the first and `stride` is the distance to the next, so
an array of the caller's own structs needs no repacking.

```c
size_t pushed = 0;
subetha_ring_try_push_many(ring, producer, (const uint8_t *)events,
                           sizeof events[0], sizeof events[0].payload,
                           count, &pushed);
```

A batch stops at the first operation the object refuses and reports how
many it completed, so a full ring leaves the rest for the caller's next
call. It returns `SUBETHA_OK` when at least one completed and the
refusal's own code when the first one was the one that failed.

Measured on the AVX-512 Windows build host: sixty-four pushes and
sixty-four pops through the batch forms take 1.23 us, and the same one
hundred and twenty-eight operations one call at a time take 2.68 us.

## A hold, a permit, a pin and a ticket are tokens

Everything else in this ABI is named by a handle. These four are not:
they are taken and given back in a loop, and a handle is the wrong shape
for that. Issuing one allocates on the heap and takes two mutexes;
closing one takes a third and runs a process-wide barrier to prove no
call is inside it.

A token is a `uint64_t`. Taking one is a compare-exchange and giving it
back is another; nothing is allocated and no lock is taken. Measured on
the AVX-512 Windows build host: a write lock acquire and release costing
3.1 ns of direct work reads 29.5 ns through the ABI as a token, 49.2 ns
while seven other threads are inside calls of their own, and 29.0 ns
once they have left. An epoch pin and release reads 34.4 ns against
5.2 ns direct, and a semaphore acquire and release 32.3 ns against
6.6 ns, in the range of every other family's pair.

A cross-process waker park and release reads 5.3 ns of direct work and
48.8 ns through the ABI, and a lazy value's `try_get` on a published
value 2.4 ns and 7.8 ns. The waker's ABI form also claims a hold-table
slot and gives it back, which is what lets a second release of the same
token be refused, so its figure covers that alongside the boundary.

A token carries a tag bit that no handle has, so the two cannot be
confused at the boundary: `subetha_handle_destroy` refuses a token and
says so, and a release refuses a handle. Destroying the object that
issued a token still gives that token's hold back.

```c
uint64_t hold;
subetha_rwlock_try_write(lock, &hold);
/* ... the critical section ... */
subetha_rwlock_unlock(lock, hold);
```

`subetha_semaphore_release`, `subetha_pin_release` and
`subetha_ticket_publish` are the same shape, each taking the object the
token came from.

A token is refused rather than misread. Each slot carries a generation
that steps on every release, so giving one back twice is refused, and so
is a token from a hold that ended whose slot has been taken since - which
a bare index could not tell apart. An all-zeroes token, which is what an
uninitialized variable holds, names nothing.

Two consequences worth knowing. A token belongs to the handle that issued
it: two handles on one lock share the lock, but a token taken through one
is refused by the other. And destroying a handle gives back every hold
still outstanding on it, because the object holding them goes at the same
time - without that, the lock file would say held with nothing able to
release it.

Three families take a shape of their own, because their item is not a
uniform payload. A vec push answers with the index the element landed at
and an arena intern with the reference naming the bytes, so
`subetha_vec_push_back_many` and `subetha_arena_intern_many` take an
`out_indices` or `out_refs` array and fill one word per item that landed:
the answer is the point of the call, and another process may append
between two batches, so a caller cannot work the indices out from the
length it read beforehand. The map's item is a key and a value, which a
caller already holds as two columns, so `subetha_hashmap_insert_many` and
`subetha_hashmap_get_many` walk two strided arrays rather than making it
pack pairs it does not have.

```c
uint64_t at[64];
size_t pushed = 0;
subetha_vec_push_back_many(vec, (const uint8_t *)rows, sizeof rows[0],
                           sizeof rows[0].element, count, at, &pushed);

size_t inserted = 0;
subetha_hashmap_insert_many(map, (const uint8_t *)keys, sizeof keys[0],
                            (const uint8_t *)values, sizeof values[0],
                            count, &inserted);
```
